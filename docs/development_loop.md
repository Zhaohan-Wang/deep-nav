# DeepNav 制作与验证循环

每次修改遵循同一顺序，禁止跳过失败阶段继续堆功能。

1. **数据先行**：在 `MissionCatalog` 写清关卡目标、时限、尝试次数、扰动槽位和路线检查点。
2. **语义检查**：运行 `tools/mission_audit.gd`，检查 ID、起终点利用率、天体间距、路线是否侵入排斥区、事件门能否覆盖侧向绕行，以及每条小行星带与路线的关系。
3. **可视化检查**：查看 `artifacts/maps/*.png` 长条结构图，确认进场、挑战、反应、安全门和恢复段构成可解释节奏；不使用 SVG。
4. **流程检查**：逐一实例化标题、选关、游戏场景，任何脚本错误都判定失败。
5. **物理与一致性检查**：每关从 180 个角度扫掠飞船碰撞球；测试正面顶墙和沿边滑行；逐颗核对三维岩块的坐标与碰撞状态是否等于星图共享布局。
6. **Metal 图形实跑**：自动截取第四关起点、中段和边界附近的真实分屏 PNG；运行日志中出现脚本、着色器或多边形错误立即失败。
7. **重写**：任何一层失败都回到相应数据或实现修正，再从第 2 步开始。

统一命令：

```bash
tools/validate_project.sh
tools/validate_runtime.sh
```

成功标志：

```text
DEEP_NAV_FULL_VALIDATION_OK
DEEP_NAV_RUNTIME_VALIDATION_OK
```

## 模式边界

- **预览模式**：普通体验，不写正式数据。
- **调试模式**：显示尚未锁定的参数与结构信息；用于调时限、距离、难度和扰动槽位。
- **实验模式**：创建 session，只追加写入输入、事件和独立量表记录。调试标记会随 session 写入，防止误混为正式样本。

## 尚未锁定的实验参数

- 航点冷却当前为 2 秒。
- 航点最大距离当前为 72 世界单位。
- 扰动幅度、触发位置和明确/模糊归因条件尚未写死。
- 关卡时限是首轮可玩性基线，必须通过调试模式试飞后再锁定。
