# DeepNav 实验数据说明

## 本版固定方案

- 组号只收正整数，保存为 `D001` 这类研究编号，不收姓名或关系信息。
- 奇数组为 `explicit`：异常发生时显示系统成因。
- 偶数组为 `ambiguous`：只显示同等强度的客观异常，不说明成因。
- 参与者始终记为 `D001A` / `D001B`；岗位可在领航员和驾驶员之间变化，但参与者编号不变。
- Mac 内置键盘固定属于屏幕 A，唯一一把外接键盘固定属于屏幕 B；角色认领后，驾驶员键盘只负责 WASD，领航员键盘只用 E 开关星图。
- 第 1–2 个组号块中 A 在屏幕 A，第 3–4 个组号块中 A 在屏幕 B，之后循环。
- 一关只受最大时间限制。解体次数不结束任务，玩家可在时限内从起点或已抵达的中继站继续。
- 保留关末结果页和双人独立量表，不增加途中问卷。量表先反馈客观事件，再询问事件归因、搭档状态信任和系统状态信任。
- 知情同意书在线下签署，游戏不保存签名图像或姓名。

## 条件提示

正式任务 03 的航点在预定门处偏转 13°。正式任务 04 的飞船在预定门处受到一次横向冲量。

明确条件显示“磁暴造成航点方向偏移”或“太阳风剪切造成飞船横向偏移”；模糊条件只显示“航点方向出现偏差”或“飞船出现横向偏移”。物理效果、数值、显示时长和触发位置保持相同。

## 关末量表（event-attribution-2.2）

量表的归因对象是本关的具体航向事件，不再询问宽泛的“任务结果最主要由什么造成”。第一页先显示系统记录：严重航向偏离次数、预设航点/横移事件次数、碰撞和解体次数。严重航向偏离的操作定义为：飞船速度不低于 3、距离当前航点至少 8 个世界单位时，船头与航点方向相差至少 60° 并持续至少 2 秒；事件需恢复到 40° 以内才可能重新计数。该定义用于运行时判定和论文报告，不在玩家量表中展示。

驾驶员和领航员使用相同答案编码，但看到岗位化题干：编码 1 始终是“自己的岗位行为”、2 是“搭档的岗位行为”、3 是“导航信息或显示”、4 是“飞船的操控响应”、5 是“航行环境”、6 是“多种原因共同作用”、7 是“信息不足，无法判断”。每个选项同时给出落点、时机、路线、仪表、转向、速度、外力或障碍物等短例子，帮助被试区分来源，但不暗示哪一类才是正确答案。搭档能力/可预期性题目也分别指向驾驶员操控或领航员航点安排。

成功和失败使用不同的上下文提示，明确要求被试不要把整局结果当成归因对象；核心事件归因题和量尺保持一致，以便跨结果比较。搭档与系统各自测量能力或可靠性、可预期性、后续依赖意愿三个状态条目。这里的条目是为高频关末重复测量设计的短量表，分析时不能冒充未经删改的既有完整量表。

## 实时操作

`frames.csv` 每个物理帧记录：

- 屏幕 A/B 对应的稳定参与者编号和当前岗位；
- 两个席位的虚拟光标坐标及左键状态；
- 驾驶员原始推进轴和转向轴；
- 飞船位置、速度、航向、角速度、油门、船体、边界接近度；
- 当前航点状态和坐标。

`events.csv` 记录低频离散动作和结果，包括角色认领、岗位/设备交换、航点原始请求与系统实际采用坐标、碰撞、解体、复活、中继站、扰动触发、严重航向偏离、成因条件、任务结算和量表答案。每行带单调时钟、会话经过时间、物理帧号、参与者、席位和岗位。

键盘按下/释放和领航员开关星图也作为离散事件记录。F6 只交换两只鼠标的屏幕映射，不改变两把键盘的固定席位。

## 非阻塞写盘

游戏主线程只把 CSV 行放进内存队列。专用 writer 线程独占三个 CSV 文件，每秒批量刷新。若磁盘异常慢，队列最多保留 6000 个待写帧；超过后宁可标记丢帧数，也不阻塞游戏。`session_end` 事件保存总丢帧数。

## 原始录音

macOS helper 使用系统默认输入设备，把整场录音流式写为 16-bit PCM CAF。录音在独立进程中进行，内存不会随实验时长增长，也不会占用游戏帧。

首次正式实验前执行：

```bash
tools/build_macos_audio_recorder.sh
```

第一次开始实验时，macOS 会请求麦克风权限。现场应先用测试组号做 30 秒试录，确认：

1. `audio_metadata.json` 最终状态为 `complete`；
2. `written_frames` 大于 0；
3. CAF 能播放且没有使用错误的输入设备；
4. `session_start` 中 `audio_started` 为 `true`。

不要在真实参与者讲话时运行自动录音测试；项目校验只检查 helper 能否编译，不会主动开启麦克风。
